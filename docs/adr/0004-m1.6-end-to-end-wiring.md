# ADR 0004：M1.6 端到端串通实现选择

日期：2026-05-14
状态：已采纳

## 背景

M1.6 把 M1.1-M1.5 各部件串成一条完整端到端链路，涉及以下实现层决策：

## 决策 1：raw_events() + status_events() 双接口

**问题**：M1.6 要上行队列能传 game_status 和 echo 两种消息，但旧代码只有
`status_events()` 返回 `GameStatus` 对象。

**选择**：新增 `raw_events()` 方法 yield 原始 `dict[str, Any]`，
`status_events()` 改为 `async for raw in self.raw_events()` 并过滤 echo 消息。

**理由**：
- 向后兼容：现有所有调用 `status_events()` 的代码（tests / M1.2 smoke）不需要改
- 可扩展：未来更多消息类型（snapshot / unit_info）可直接走 `raw_events()`，
  不用改接口

## 决策 2：`_dispatch_upstream` 在 WS 层分流

**问题**：`_status_pump_loop` 原来直接把 game_status 推给手机；加了 echo 之后需要分流。

**选择**：抽取 `_dispatch_upstream(raw)` 方法，`_status_pump_loop` 改为
`async for raw in gp.raw_events(): await _dispatch_upstream(raw)`。

**理由**：单职责；`_dispatch_upstream` 独立可测（直接调测试，不需要拉起整个 pump）。

## 决策 3：echo_callback 作为参数传进 make_bot_class

**问题**：`_run_command_with_echo` 要在 `on_player_command` 完成后推 echo，
需要访问上行队列或回调。

**选择**：给 `make_bot_class` 加 `echo_callback: Callable[[str, str], None] | None`
参数，通过闭包让内部的 `_run_command_with_echo` 协程直接调用。

**理由**：
- `make_bot_class` 是工厂函数，闭包是该模式的标准做法
- 不需要把 `up_q` 传进 bot（bot 里不应直接持有进程间 Queue）
- 向后兼容：echo_callback=None 时跳过推送

## 决策 4：`importlib.util.find_spec` 替换 `try/import ares`

**问题**：`_build_bot_class` 原来用 `try: import ares` 检测 ares 是否可用，
ruff 报 F401 unused import。

**选择**：改用 `importlib.util.find_spec("ares") is None` 做探测。

**理由**：语义更清晰；符合 ruff 建议；不引入副作用（import ares 会触发 ares 初始化）。

## 决策 5：task 管理（Gap 3 spike 结论）

**问题**：ares `on_step` 里 create_task 的任务如何防 GC、处理异常。

**选择**：
- `_VoiceCraftBot._cmd_tasks: list[asyncio.Task[Any]]` 持有引用
- `task.add_done_callback(_on_cmd_task_done)` 自动移除 + 异常日志
- `on_end` 里 `await asyncio.gather(*_cmd_tasks, return_exceptions=True)` 等待清空

**理由**：
- asyncio 的 weak reference 规定：task 必须被强引用持有才不会被 GC
- done_callback 方案不需要 await，不阻塞 on_step
- return_exceptions=True：不因单个 task 异常取消其他 task
