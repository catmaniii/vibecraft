# VibeCraft 改进计划（2026-06-04）

> 依据：`docs/research/2026-06-04-voice-command-product-review.md` 产品评审 + 用户对 4 个产品岔路的定调。
> 本文是**路线 + 设计提案**层级；每个工作包的 TDD 实施细节另起 plan。

---

## 0. 用户定调 → 4 条原则/方向

| 岔路 | 定调 | 落成原则/方向 |
|---|---|---|
| 1 接管/手操 | **否决**。降低 RTS 门槛是第一性，把操作引回来是本末倒置 | **纯语音**。玩家一开口 bot 立即全让位（语音收权）；**不做**键鼠/手机微操面板 |
| 2 bot 能力 | **刻意压低**，给玩家留存在感；bot 有运营+战斗两层，目前只做了"实时战术"干预，缺"实时运营"干预 | **双栏干预模型**：左[战术]｜右[运营]，两层都"玩家选姿态、bot 执行"，bot 不自主决策 |
| 3 先执行可撤销 | 要做；取消不只撤上一步，还要**恢复被覆盖的原指令** | 做"先执行+可撤销"中间档 + **撤销恢复栈**，边界 case 穷尽 |
| 4 bot 自评 | 要做；趣味 + 让玩家了解 bot 能力边界 | 关键**自主**动作后 bot 给一句自评（自夸/认错都行），不评玩家的指令结果 |

**贯穿原则（来自定调 2）**：bot 在战术和运营两层都是**执行玩家选定的姿态**，智能/决策权留在玩家手里。这同时回答了评审里"meta 委派/动态自治需要强 bot"的担忧——我们**不走 bot 自主那条路**，走"玩家用低 APM 选姿态、bot 机械执行"，既降 APM 又保 agency。

## 1. 核心产品结论：双栏实时干预模型

```
┌─────────────────── 实时干预面板 ───────────────────┐
│  左栏：实时战术选择          │  右栏：实时运营策略选择   │
│  （军队现在怎么打）          │  （运营引擎现在怎么转）    │
│  ───────────────            │  ───────────────         │
│  强制全体进攻                │  滚雪球/攀经济            │
│  试探性进攻                  │  均衡运营（默认）         │
│  全军防守                    │  暴兵一波                 │
│  全军坚守                    │  速科技/憋后期            │
│  全军撤退                    │  龟缩防守                 │
│  火力侦查                    │  ─ 一次性 ─              │
│  派单位探路                  │  马上扩一个 / 把钱花出去   │
│  （已有，combat_intent）     │  （新建，macro_stance）   │
└────────────────────────────────────────────────────┘
        ↑ persistent stance + 一次性动作，两栏同构
        bot 读 stance 执行；玩家沉默时按当前 stance 兜底（不是恒定 Medium）
```

左栏=已有的 `combat_intent_override`（经 sharpy hook 压制战斗决策树）。右栏=新建 `macro_stance_override`，被 auto-pilot 的运营逻辑读取。**两栏结构同构、心智模型一致**。

## 2. 工作包总览（按优先级 + 依赖排序）

| 包 | 名称 | 类型 | 依赖 | 价值 |
|---|---|---|---|---|
| **A** | 控制边界可视化 | 快赢 | — | 玩家看得到"哪些单位归我指令/哪些 bot 自由"；是双栏透明度 + 撤销 UX 的基础 |
| **B** | 状态属性指代（残血的/受伤的…） | 快赢 | — | 补语音核心原语；也是 C 的高频触发场景 |
| **C** | 先执行+可撤销+恢复栈 | 中 | A（边界可视化辅助）| 中置信不再死胡同；撤销能恢复被覆盖的原指令 |
| **D** | 实时运营策略层（右栏） | 大（核心新功能）| — | 补齐运营干预层，双栏成立；降 APM 的主力 |
| **E** | bot 关键动作自评 | 中 | — | 趣味 + 能力边界认知 + 校准依赖 |
| **F** | 语音收权 | 小（原则项）| — | 玩家开口 bot 让位，落实定调 1 |

建议节奏：**A+B 先做（快赢、互不依赖）→ C 与 D 并行（C 偏前端+Director、D 偏 bot 运营逻辑）→ E 收尾 → F 随手做**。

## 3. 【WP-D】实时运营策略层 · 设计提案（你点名要规划的）

### 3.1 设计原则
- **对齐战术栏**：一组持久姿态 preset（互斥，选一个）+ 少量一次性动作，跟左栏 7 个按钮同构。
- **姿态是玩家意图的打包**：玩家不想分别调"农民/扩张/科技/产线"四个旋钮，而是按一句话意图选（"我要滚雪球""我要暴一波"）。每个 preset 内部打包多个运营轴。
- **bot 只执行不决策**：preset 决定运营**倾向**，具体执行用现有 override 机制（production/expansion/tech/structure），bot 不自己判断该攀经济还是暴兵。

### 3.2 运营姿态 preset 清单（5 持久 + 2 一次性）

| 运营姿态（持久） | 玩家意图 | 打包的运营轴 | 映射 |
|---|---|---|---|
| **滚雪球 / 攀经济** | "拉开经济差" | 多造农民补满分基 · 激进扩张 · 压低产兵 · 科技标准 | expansion_override↑ + 农民优先 + 产兵节流 |
| **均衡运营（默认）** | 默认稳健 | 经济军事兼顾 · 稳健扩张 | 当前 auto-pilot 行为 |
| **暴兵一波** | "打 timing / 一波流" | 停造农民 · 不扩 · 钱全砸兵 · 不出新科技 | production 全开 + expansion 冻结 + 农民封顶 |
| **速科技 / 憋后期** | "憋航母/大后期/科技压制" | 优先科技建筑+升级 · 控制扩张 · 攒科技单位 | tech_override 链 + 产兵节流 |
| **龟缩防守** | "被压了，稳住" | 不扩 · 加固防御建筑 · 保守生产 | 防御 structure_override + expansion 冻结 |

| 一次性运营动作 | 玩家意图 | 映射 |
|---|---|---|
| **马上扩一个** | "现在开矿" | 一次性 expansion_override +1 |
| **把钱花出去** | "钱囤太多了" | 一键铺产能/补建筑/补农民消化资源 |

> 取哪几条先做、preset 名字（"滚雪球"还是"猛攀经济"？）要你定。我建议 MVP 先做**滚雪球/暴兵/均衡**这条最核心的"经济↔暴兵"轴（最高频、最能体现降 APM），龟缩/速科技二期。

### 3.3 跟现有 override 的关系
- 现有 `production_override`/`expansion_override`/`tech_override`/`structure_override` 是**一次性精确指令**（"出 4 追猎""补到 3 矿"）——保留，玩家要精确控制时用。
- 新 `macro_stance` 是**持久倾向姿态**——玩家不想逐条管时设一个姿态，bot 按姿态自动调运营。
- 二者叠加：精确 override 优先级高于 stance（你明确说"出 4 凤凰"时不被"暴兵地面"姿态盖掉）。

### 3.4 bot 端
- 新增 `macro_stance_override` 字段（parallel `combat_intent_override`），写 knowledge.vibecraft。
- auto-pilot 的运营决策（补农民/扩张/产兵/科技）读这个字段调倾向。**这是新逻辑**——当前 auto-pilot 是恒定兜底，要让它"按 stance 调"。注意：仍是机械执行姿态，不是让 bot 变聪明（守定调 2）。
- 风险：运营逻辑改动要测"后劲"（CLAUDE.md 的 build 体检三维度——supply 单调涨、不摆烂），用 build_acceptance 验。

## 4. 【WP-C】撤销/恢复栈 · 边界 case 穷尽（你强调要全）

**机制**：每条 directive 提交时，对它**抢占/覆盖**的每个单位/姿态，快照"被覆盖的上一个状态"（displaced record）。撤销时按 displaced record **per-tag 逐个恢复**。

| # | 场景 | 撤销 D_new 后的正确行为 |
|---|---|---|
| 1 | D_new 抢了正在执行 standing order（守瞭望塔）的单位 | 单位**恢复 D_old**（回去守瞭望塔，重发 primary_action） |
| 2 | D_new 抢的是 bot 自由单位（无 D_old） | 单位**交回 bot 自由调度** |
| 3 | 撤销时 D_old 已完成/过期/被释放 | 无法恢复 → 交回 bot + 卡片提示"原指令『守瞭望塔』已结束，单位交回 bot" |
| 4 | 单位已死 | 静默跳过该 tag |
| 5 | 多层覆盖 A→B→C | 每条记自己覆盖的上一个；撤销 C **恢复 B**（不是 A）。per-tag LIFO 栈 |
| 6 | D_new 覆盖多单位、各自 previous 不同（残血撤回抓 3 个：1 个原守塔、2 个 bot 自由） | **per-tag 各自恢复**：1 回去守塔、2 交回 bot |
| 7 | 运营 stance 覆盖（暴兵一波 盖了 攀经济） | 撤销 → **恢复攀经济 stance** |
| 8 | "先执行+可撤销"的可撤销窗口 | 有时效（N 秒 或 被下一条同范围指令 supersede）；过期后动作"固化"，不再一键撤销（但仍可下新指令） |
| 9 | 撤销之后又反悔 | 不做"撤销的撤销"（避免无限栈）；撤销后回到 D_old，要改再下新指令 |
| 10 | D_new 是一次性 vs 持久 | 一次性（move 到点）撤销=召回到原状态；持久撤销=解除该 standing order + 恢复 previous |

**实现要点**：现有 `_standing_order_tags`(did→tags)、`_unit_semantics`、board.revoke 已有基础；新增 per-directive 的 `displaced_map`（tag→被它覆盖的 prior 控制源），revoke 时重放 prior。这块要单独写细 spec + 覆盖上面 10 个 case 的单测。

**与 WP-B/WP-A 协同**：撤销提示里要能说清"撤销后这 3 个追猎回去守瞭望塔"——靠 WP-A 的控制边界数据 + WP-B 的"残血的"指代，三者天然咬合。

## 5. 【WP-E】bot 关键动作自评 · 设计

- **触发**：仅 bot **自主**做的关键事件结束时（不是玩家明确下令的——评玩家指令结果=质疑玩家决策，碰 agency 红线，定调 4 也强调评的是"bot 自己这一波"）。关键事件候选：bot 自主打的一波交战结束、bot 自主骚扰收尾、丢了一个分矿、一笔大的兵力交换。
- **内容**：一句话，有人设，**诚实**报结果——赢就自夸、亏就认错：
  - "这波守家稳住了，换掉对面 6 个农民 👍"
  - "这波骚扰我亏了，3 凤凰换 4 农民，下次少托付给我"
- **价值**：①趣味（AI 自夸/认错本身有意思）②让玩家了解 bot 能力边界（校准依赖：知道 bot 守家稳、骚扰菜）。
- **展示**：transient "bot 旁白"一行 + 落历史指令流可回看。
- **技术**：bot 检测"一波自主事件收尾"（telemetry 有 army delta/kills/losses）→ 取战果数据 → LLM 生成人设化点评（或模板兜底）。注意频率克制，别唠叨。

## 6. 快赢两包（WP-A / WP-B）

**WP-A 控制边界可视化**：snapshot 加 `controlled_units`（按 directive 分组的 tag 列表 + 控制源类型：玩家指令/bot自由/编队）；web 端单位/编队区分显示"这些归你的指令、这些 bot 自由调度"。后端账本（`LLM_CONTROLLED`/Reserved）已存在，纯加暴露 + 渲染。

**WP-B 状态属性指代**：Selector 加 `health_below`/`shield_below`/`age_below_s` 等过滤字段 + Director resolver 求值 + few_shot 补例（"残血的追猎撤回来""刚折跃那批叉子上去"）。

## 7. 还需你拍的小决策

1. **运营 preset 取哪几条先做 + 命名**：建议 MVP 先做"滚雪球/暴兵/均衡"经济轴三选一；龟缩/速科技二期。preset 名字风格（黑话"滚雪球/暴一波" vs 中性"攀经济/暴兵"）你定。
2. **可撤销窗口时长**：撤销 offer 几秒后固化？（语音流不能等太久，但太短玩家来不及改。建议 8-12s，实测调。）
3. **bot 自评的频率/触发面**：只评几类关键自主事件（避免唠叨）。要不要也在玩家**明确托管**给 bot 的事上评（这不碰 agency，因为是玩家主动交的）？
4. **运营层是否动 ADR 0006**：右栏让 auto-pilot"按姿态调运营"，本质是给恒定兜底加了个玩家可调的方向盘——不是抬高 bot 智能上限（守住定调 2），但要更新 ADR 0006 的"不做实时运营调整"那条描述。确认这个边界对。
