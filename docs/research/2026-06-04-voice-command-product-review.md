# VibeCraft 语音指挥 · 产品深度评审

> 2026-06-04 · 视角：游戏产品经理 · 方法：deep-research workflow（多源检索 + 对抗验证）+ 独立批判 subagent（回代码核实）+ 综合
> 配套工件：`docs/research/2026-06-04-capability-baseline.md`（当前能力基准）
> 范围对齐（与用户）：**执行类指令 + 玩家掌控 AI 执行者的信任机制**；**排除信息查询**（UI 已覆盖）。人群：**广谱**（手操衰退老玩家 / 身体受限玩家 / 躺平回归休闲）。

---

## 0. 一句话结论

> **指令空间做到了 90 分，研究认定的"主菜"——信任 / 掌控机制——几乎没动。当前产品是"语音遥控一个弱兜底 bot"，而玩家真正需要的是"一个能在多个自治高度间动态协商的副驾"。指令越全，越凸显玩家在逐条手动驾驶，而不是托管。**

这不是说现状差——指令覆盖的扎实是真实资产。但若把产品愿景定在"让手跟不上的人继续享受 SC2 的决策乐趣"，**瓶颈已经从'能不能表达指令'转移到'敢不敢把事交出去、交出去后还看不看得懂'**。

## 1. PM 视角：这个产品在赌什么

游戏 PM 评一个产品，先看四件事，逐一套在 VibeCraft 上：

| PM 关注点 | VibeCraft 的现状判断 |
|---|---|
| **核心 JTBD（玩家雇这产品干嘛）** | "我脑子还在、手跟不上 / 用不了键鼠，但我想继续以**我的决策**赢下一局 SC2。" 决策乐趣是内核，手操是被外包的部分。 |
| **核心循环** | 玩家观察（手机看战场）→ 语音下令 → bot 执行 → 看结果 → 再下令。**当前循环的'下令'密度过高**——因为 bot 兜底弱，玩家得逐条驱动，循环更像"遥控"而非"指挥"。 |
| **玩家分层 / 上手曲线** | 三类人群的痛点其实**不同**：老玩家要"少操作但保战术深度"；身体受限玩家要"语音能完成整局、不依赖他人"；躺平休闲要"低投入也有掌控感"。当前产品对三者用**同一套逐条指令**，没有按人群提供不同的"托管程度"。 |
| **北极星候选指标** | "玩家用语音**打完整局**且主观觉得**是自己在指挥**的比例"。这个指标同时压住了 agency（研究的信任前提）和完成度（无障碍目标）。当前没有任何机制服务这个指标的"觉得是自己在指挥"那一半之外的"愿意把杂事交出去"那一半。 |

**研究最强的一条论断**（多源、对抗验证通过）：玩家要的不是"全自动"（"全自动还有什么乐趣"），也不是"全手动"，而是**保留决策权、外包执行、且能在不同'高度'和不同'游戏阶段'动态调整把多少交给 AI**。这正是 VibeCraft 当前最薄的一层。

## 2. 玩家需要什么（研究得出的需求分类法）

> 来源经 3 票对抗验证（24 源 / 104 claim → 23 确认 / 15 综合）。唯一 SC2 原生先例：arXiv 2508.16580《Adaptive Command》（LLM 解析 + 行为树执行 + 语音接口，12 人研究，"尤其惠及新手与残障玩家"）。其余信任/无障碍/指代文献来自人因、无障碍游戏、NLP——**域迁移见 §8**。

**A. 指令空间（执行类）**
- A1 全 RTS 动作空间：宏观（经济/build/科技/扩张/产线）、军队控制（攻/守/移动/站位/撤/集结/包抄）、微操（集火/风筝/技能 storm·forcefield·blink/阵型/分散/目标优先级）、侦查视野、编队、多步与条件化打法（timing/空投/骚扰/all-in/proxy/runby）。【高置信】
- A2 **持久意图 / standing order**（"持续扩张""守住这"，无新指令则保持），非一次性。【高置信】

**B. 掌控 / 信任机制（研究重头）**
- B3 **委派粒度比"开/关"细**：跨任务模型的多个"高度"（单位 / 编队 / 全军 / "帮我管运营"），玩家用语音在高度间切换（Playbook，Miller & Parasuraman）。【高置信】
- B4 **动态分阶段自治**：自治程度连续重协商——平稳运营期高自治，局势不确定 / 不可逆 / 关键团战时玩家收权。【高置信】
- B5 **纠正-覆盖优于微操**：人给定向纠正、AI 保留执行控制时团队表现最佳。【中高置信，2-1】
- B6 **持久委派边界 + 随时全控接管 / 交还**（take over / hand back）。【高置信】
- B7 **保留玩家决策权**（agency = 信任前提）。【高置信】
- B8 **校准依赖**（calibrated reliance）非最大信任：玩家信任要匹配 AI 真实能力。【高置信】
- B9 AI **沟通能力与局限**，信任靠反复交互**挣来**。【高置信】
- B10 **透明文字本身不够**，要配实证能力展示。【高置信】
- B11 消除**自治混淆**：清晰标示 AI 在做什么、控制边界在哪。【高置信】

**C. 无障碍**：软件 copilot 部分自动化是被验证的无障碍机制，**减少玩家需管理的指令数**、消除对人类帮手的依赖。【高置信】

**D. 语音 UX**
- D12 **间接指代是核心原语**：玩家按属性指代（"受伤的那些""左边那群""血最少那个"），不报 ID；grounding 是独立难题。【高置信】
- D13 指代消解有不可消除错误率（~82-87%）→ **交互式澄清**、不静默瞎猜；但澄清往返要权衡 **>1.5s 破坏战斗流**。【高置信】
- D14 **错误纠正 / 自我修复是一等信任机制**：AI 犯错后承认并改正大幅提升评价；但没犯错乱纠正反降分。【高置信】

**被对抗验证驳回（别建在上面）**：逐动作单一归属控制边界（0-3 否）；混合主动 = 全遥操 / 全自治二元切换（1-2 否）。

## 3. 需求 vs 现状 · 缺口矩阵

> 判定经独立 subagent 回代码核实（区分"schema 有字段" vs "LLM 真被教会" vs "执行接通" vs "玩家看得到"）。对"部分满足"从严——半成品不算满足。

| # | 需求 | 判定 | 缺在哪（证据） |
|---|---|---|---|
| A1 | 全指令空间 | ✅ 已满足 | 17 DirectiveType + 15 verb + 13 战术 verb + 三族 cast_ability；微操/空投/编队/巡逻/代理建造都有 few_shot。**产品最扎实部分。** |
| A2 | 持久意图 | ✅ 已满足 | `ScopeKind.PERSISTENT` + `tactical_objective(persistent)`。 |
| B7 | 保留玩家决策权 | ✅ 已满足 | rules 严令 LLM 绝不替玩家判断合理性/时机/资源。**做得到位。** |
| B5 | 纠正-覆盖 | 🟡 部分 | 覆盖机制强（combat_intent_override 经 sharpy hook 压制决策树）；但被纠正的**基线 bot 太弱**（Medium AI 兜底），"纠正"退化成"从零微操"。 |
| B10 | 透明需实证 | 🟡 部分（弱） | 透明度=Command Cards + snapshot + 历史三层，**恰是研究说"不够"的轻量文字**；缺"让玩家看到 bot 把某事做漂亮"的实证。 |
| B11 | 消除自治混淆 | 🟡 部分（关键半成品） | 后端有 `LLM_CONTROLLED`/Reserved 账本，**但 snapshot 不暴露 per-unit 谁在控**（telemetry 核实无字段）。玩家分不清 12 个追猎里哪些在执行自己指令、哪些 bot 自由调度。 |
| D12 | 间接指代 | 🟡 部分（缺最核心一类） | Selector 支持 类型/编队/位置/任务 指代，**但无 health/shield/age**——"残血的""受伤的""刚造出来那批"说不了。 |
| D13 | 澄清不瞎猜 | 🟡 部分 | 有 ClarificationRequest + confidence 阈值；**但是"全或无"一次性弹层**，无 >1.5s 战斗流权衡的"先猜+可撤销"中间档。 |
| C | 无障碍·减少指令数 | 🟡 部分（做反了） | 语音输入达成；但因缺 B3/B4，玩家靠**逐条指令**驱动弱 bot，指令密度反而高。"帮我管运营"能省几十条，恰没有。 |
| B3 | 委派粒度（高度） | ❌ 缺失 | 只有 对象粒度（单位/编队/全军），**无"管理高度"维度**；无 directive 把"一类决策的自治权"交给 bot。 |
| B4 | 动态分阶段自治 | ❌ 缺失 | ADR 0006 标定 auto-pilot = 恒定 Medium AI 兜底，**明确不做自动转阶段**；bot 无"关键时刻 vs 平稳期"感知。 |
| B6 | 接管 / 交还 | ❌ 缺失 | src 下 `接管/交还/takeover` 零业务命中；group_clear ≈ 半个"交回 bot"，**无反向"我接管"**；且 **PC 端无键鼠**，"我自己手操"物理上无处落地（形态张力，见 §7）。 |
| B8 | 校准依赖反馈 | ❌ 缺失 | snapshot 只有宏观数值，**无 bot 自评/置信/历史成功率**；玩家无从校准。 |
| B9 | 沟通能力与局限 | ❌ 缺失 | bot 从不说"我不擅长 X""这波可能守不住"；interpretation 只复述听懂了什么。 |
| D14 | 自我修复 | ❌ 缺失 | 自我修复只在 LLM **内部 schema 校验失败时静默 retry**，玩家不可见；对玩家失败只有"识别失败"死胡同。无"我理解成 A，其实你要 B 吧？"通道。 |

**统计**：14 项核心需求 + 无障碍 → 已满足 3 / 部分 6 / 缺失 6。**已满足的全在"指令空间"和"agency"，缺失的全在"信任/掌控/自我修复"。**

## 4. 没考虑到的场景 / 交互盲点

1. **meta 委派（"帮我管运营""微操交给你"）— 完全空白。** 所有 directive 都是"做一件具体的事"或"切预定剧本"，没有"把一**类决策**的自治权授权给 bot"。这是 B3 的本质，也是 C（减少指令数）的唯一正解。**战略缺口**。
2. **动态分阶段自治 — 概念不存在。** 理想：平稳期 bot 自主补农民/扩张（高自治），探测大战临近时**主动推镜头 + 降自治等玩家发话**。当前恒定弱兜底，团战不交还、平稳期也不真自主。
3. **接管 / 交还 + 形态张力 — 半边缺 + 架构未决。** 无"我接管这批"反向机制；更根本：**PC 无键鼠**把"我自己手操"这条路堵死了——研究假设玩家能接管手操，我们形态不支持。"手机上的'我来'到底是什么"是个未答的架构问题。
4. **自治混淆可视化 — 数据有、UI 无。** 后端知道每个 tag 谁在控，玩家端 snapshot 完全不暴露。**最接近"快赢"——数据现成，缺一层渲染。**
5. **状态属性间接指代 — Selector 缺字段。** "残血的撤回来""受伤的拉回家""刚折跃那批上去"——SC2 玩家极高频（保血量、保经验单位），完全说不了。
6. **自我修复（misparse 主动改正）— 零覆盖。** 只有内部静默 retry；研究称这是最强信任机制之一。
7. **校准依赖反馈 — 无信号。** 玩家无法得知"bot 守家稳、但骚扰常送"；只能靠不可靠的体感校准。

## 5. 体验改进空间（功能可用但体验弱）

- **透明度全是"我下过什么"，没有"bot 此刻在自主做什么"。** 玩家沉默时屏幕上无"bot 正在补农民/扩张"的叙述——B11 的"标示 AI 在做什么"没达成。
- **澄清是"全或无"一次性弹层，没有战斗流权衡。** 缺"先按最佳猜测执行 + 显著标示'我猜你要 X，点这改'"的中间档（项目早先已去掉 1.5s commit 延迟说明团队已意识到延迟伤体验，但澄清路径没跟上这个判断）。
- **失败只说"识别失败"，不给修复路径。** 哪怕加"没听懂'那个'指哪个，你最近提过追猎/凤凰，要哪个？"也比死胡同强。
- **控制边界不可查 → 玩家不敢委派。** 看不到"委派出去的单位现在归谁管"，玩家倾向事必躬亲，与"低 APM 躺平"卖点背道而驰。

## 6. 优先级路线（impact × effort）

```
            高 impact
              │
   B3 meta委派 ●        ● B11 控制边界可视化(快赢)
   B4 动态自治 ●        ● D12 状态属性指代(快赢)
  (战略, 需新机制)      ● D13/D14 自我修复·澄清降级(快赢)
              │
              └────────────────────────── 低 effort
   高 effort                          低 effort
```

**第一梯队 · 快赢（数据/机制大多已在，差暴露和扩展）**
1. **控制边界可视化（B11）** — 后端 `LLM_CONTROLLED`/Reserved 账本已存在，只是 snapshot 不暴露。改：snapshot 加 `controlled_units`（按 directive 分组的 tag 列表）+ web 单位染色/分区"这些归你指令、这些 bot 自由调度"。**纯加一层渲染，直接提升委派信任。**
2. **状态属性间接指代（D12）** — Selector 加 `health_below`/`shield_below`/`age_below_s` + Director resolver 求值 + few_shot 3-5 例。**中等改动，语音体验明显跃升。**
3. **玩家可见的自我修复 / 澄清降级（D13/D14）** — 把已有 ClarificationRequest 扩成"先按最佳猜测执行 + 一键改正"中间档（避开 >1.5s 卡顿）；失败给具体修复提示而非裸"识别失败"。**机制已在，改的是调用策略。**

**第二梯队 · 战略缺口（需要 bot 真会自己干活并讲清楚自己在干嘛）**
4. **meta 委派 / 委派高度（B3 + C）** — 新增"自治委派"语义：玩家把"运营/微操/骚扰"维度授权 bot 自主，bot 在该维度自主决策并在 Command Card 叙述自己在做什么。需要 bot 先具备**强于 Medium AI 的分维度自主能力**。建议：schema 占位 + 选 1 维度（运营）做 MVP。
5. **动态分阶段自治 + 校准依赖反馈（B4 + B8 + B10）** — bot 探测交战临近时主动推镜头 + 降自治提示玩家；事后给 per-capability 回顾（"这波守家稳/骚扰送了"）喂校准。依赖 #4 的自治基础设施，排最后。

**贯穿性天花板**：当前 **ADR 0006 把兜底封在 Medium AI、且明确不自动转阶段**——这是 #4/#5 的根本天花板。要把产品从"遥控器"升级成"副驾"，**必须先抬高这块地板**（更强的分维度兜底 AI）。#1-3 不依赖它，可立即做。

## 7. 需要你拍板的产品岔路（这几处研究给不了答案，是产品决策）

1. **"我接管手操"在无键鼠形态下到底是什么？** 研究假设玩家能随时接管手操（B6），但我们 PC 端物理无键鼠。三条路：(a) 放弃"手操接管"，只做"语音收权"（玩家发话期间 bot 完全让位，沉默才兜底）；(b) 手机上做轻量微操面板（点选 + 慢动作）；(c) 承认这是形态边界，不追求逐单位手操，转而强化"语音 + 高度委派"。**我倾向 (a)+(c)**，但这是定位问题，要你定。
2. **是否抬高 ADR 0006 的兜底地板？** 副驾形态的前提是 bot 平稳期能自己把运营打得不难看。这是一笔不小的 AI 投入。不做，则 #4/#5 永远做不动，产品停在"遥控器"。**做不做、什么时候做，要立项决策。**
3. **实时消歧策略：问 vs 猜+可撤销。** 战斗中 >1.5s 澄清往返破坏手感。倾向"高置信直接执行、中置信先猜+显著可撤销、低置信才问"，但具体阈值要靠你的人群实测调。
4. **校准依赖要不要让 bot "自陈能力"？** 给玩家看"bot 守家成功率高/骚扰常失败"能帮校准信任，但也可能让玩家对 bot 失去信心。要不要做、怎么措辞，是体验权衡。

## 8. 研究局限（诚实交代）

- **域迁移**：除《Adaptive Command》（SC2 原生，12 人小样本）外，信任/掌控文献来自 UAV/机器人/网络事件/搜救，无障碍来自通用游戏无障碍，指代来自机器人/NLP。**对 VibeCraft 的应用是类比推断**（已适当 hedge），非 SC2 直接实证。
- **量化数字是方向性、非定律**：校准解释 94.7% 表现方差来自单篇硕论单阶段；指代 82-87% 准确率来自窄二选一、GPT-4 前任务。当趋势看，别当法则引。
- **实时张力未验证**：交互式澄清在回合制机器人取放很稳，但 RTS 实时下"何时问 vs 何时按最佳猜测先做"无源可依——这是中心 UX 风险，需用我们自己的人群实测调。
